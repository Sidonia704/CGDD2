# 第二步计划：参考场景 → 约 3500 格可破坏地图

**此文件是计划，本轮不生成或重组地图。** 参考目录为 `Assets/_Starframe/assetsForCodex/scenemodel/`，保留 cggd.blend、mainstru/debri/astro/scatter.fbx。现有 v3 保存为未验收草案，不作为高保真重建的几何底稿。

## 1. 先标定，后建模

- 以 Blender 场景的对象层级、世界矩阵、相对位置为基准；读取原文件，不保存回源文件。导出只读对象/网格/实例清单。
- 对照 Unity FBX 的 mesh-local、root-local、world 三种坐标；根节点缩放分别包含 9.599648、100、0.682607 等，且有旋转。统一坐标变换一次，不能只乘某个轴的尺寸，也不能二次应用根变换。
- 四个 FBX 当前不可 CPU 读顶点。本轮只读取导入边界，没有更改 Importer。下一轮优先用 Blender/源文件提取精确顶点，或隔离副本导入；不能把旋转后的包围盒当作精确源几何。
- 将整场**最长方向**标定至约 3500 个基准格（默认 1 格=1m），其余轴按源比例保留；这不代表把每个方向强行拉到 3500。标记穹顶、断口、主平台、长悬臂和外围陨石的坐标。
- 保留“下半部采矿站/陨石带，上半部开放飞行”的设计。用一个总布局变换安置参考，而非分别乱移部件。

**交付门槛：** 三视图和整体斜视图的参考叠加、明确比例/朝向/原点；在标定一致前不批量造资产。

## 2. 按真实结构拆分独立物件

- 主站按平台层、六边形甲板、穹顶及圆形开口、胶囊/立罐、长悬臂/吊臂、桁架、设备框、管路/栏杆/散热片、断口拆成可编辑资产；不能只凭网格壳数量决定刚体数量。
- 原有 mainstru/debri 中大量很小的网格壳，先按空间位置与结构归并。原本分开的残骸和石块保持独立；本来连接的单件保持连通。
- 保留源陨石/碎片分布和尺度层次，识别可复用原型与实例。参考中的平面装饰卡片不能原样当可碰撞石块，需用三维体块原型还原其轮廓与位置。
- 每个物理资产要求六邻接连通；有意分离的内容显式拆为多个布局实例。先解决当前桁架200岛、甲板49岛、罐体等初始断连问题，不能靠自动补桥或首次挨打后批量爆散来掩盖生成缺陷。

**交付门槛：** 资产清单、对应源对象、用途、尺度、格数、连通性、布局变换；先验收一个穹顶、一个开孔平台和一根桁架，再扩展整库。

## 3. 用八种基础体块重建，回到体块工作室编辑

| 体块 | 主要用途 |
|---|---|
| Cube | 实体内部、节点、方形支撑 |
| Wedge | 曲面逐层收边、坡面和断口 |
| Slab | 薄层平台、栏板、薄肋 |
| Pyramid | 多向收尖、角部过渡 |
| Block5 / Block6 | 非对称切角和不同曲率的边缘过渡，按真实模型匹配 |
| Block7 | 1×1×2 长肋和梁段 |
| Block8 | 2×2×2 大体块、结构节点 |

- 在统一网格上求实体/空洞与表面方向，再在24个格点姿态中选真实模型；要保留负空间、孔洞、层级和桁架间距，不能用整个外包围盒填实。
- Block7/8 按工作室现有 `AddModelCells`/`modelOffset` 路径保存所有占格片段，旋转和破坏后仍正确；禁止伪装成一格模型。
- **Block8不等于占格记录减少8倍**：当前仍记录其8个物理格。不能拿大模型少一件当作伤害状态和内存也少8倍。
- 使用舰船模型和塑料材质，地图色槽只改地图颜色。八种体块要有合理用途和真实构成清单，不能仅放八个展示样品便宣称整图已采用。
- 默认以1m基准格衡量细节。距离LOD只简化视觉，不改变真实损伤格；超出单资产131,072格时，先评估同一物理体的数据分段方案或合理的真实物件拆分，不能为了绕上限把一个完整物体拆成会自行散开的刚体。

**交付门槛：** 三视图叠加核对主要轮廓、圆口、甲板间隙和支架；主要轮廓误差以约1个基准格为目标，所有八种体块均有实际用途。完全可在体块工作室打开、修改、撤销、保存和再次加载。

## 4. 性能先做小样，不能直接把当前场景加密

当前草案为199个物件、218,303格、约28,531个合并碰撞盒；已有报告冷构建约14s，但那是旧源码下的编辑器测量，不能当运行帧率保证。3500格长度也不等于只有3500个方块。

- 以整件物品为刚体，不每格创建 GameObject、Rigidbody 或 Update。渲染子块仅是单资产内部的更新单元，不是固定世界区块。
- 完整资产共享不可变几何/占格原型；重复实例尽量用共享网格和实例化。进一步评估“共享完整占格 + 每实例稀疏移除覆盖”，避免复制大量未受损格状态。
- 保留稀疏伤害：未命中格没有独立血量记录；命中才写入临时值，默认停火2s后清除记录，视作满血；被打掉的格不回来，不执行逐格回血。
- 完整资产无重力漂浮，受到撞击可被推；真实断裂后形成有碰撞、可再破坏的独立物件。默认不把微小残骸偷偷改成无碰撞粒子。
- 共享预热与分帧载入、合并碰撞盒、只更新损伤附近网格/拓扑。控制原型数量与预热内存，不能把全部不同岩石的高精网格及细分预热同时常驻当作免费优化。
- 做真正的距离视觉LOD和实例级剔除。远景仍有可命中数据；若按距离激活精细物理，必须由碰撞/弹道预测提前激活，不能只按摄像机可见性开关，也不能在切换时丢失速度、血量覆盖或破坏状态。
- 初始漂移单独调小且可重复，不能全为零却宣称有主动漂浮；也不能大幅随机旋转而毁掉参考布局。先做一组碰撞/受击小样再决定参数。

**交付门槛：** 分级规模的小场景测冷/热加载、顶点/显存、常驻状态内存、碰撞盒/刚体数、CPU/GPU帧时和首次/持续破坏峰值。先在实际 Player 验证预算，再提高密度；不以“少记录血量”代替全链性能验证。

## 5. 场景合成与验收

1. 将通过小样验收的资产按统一源变换写入独立新布局；保留旧草案和参考原文件。
2. 先站体轮廓，再断口/结构细节，再近景岩石，最后补外围碎片，逐层对照参考图；禁止用随机散布替代源布局。
3. 核对约3500格长轴、上下飞行空间、出生点净空，保存物件姿态与独立漂移数据。
4. 验证任一处受击只扣正确格；停火记录清除但洞仍在；断裂无丢格，碎块不消失、可碰撞/再破坏；连续撞击和射击不会一次产生数百个本来就断开的物件。
5. 交付体块工作室整体/站体近景/孔洞/桁架/八体块构成截图、独立物理沙盒和实测性能报告。实际关卡、敌方波次和胜负仍是后续任务，不顺带接入游戏首页。
