# 体块地图工作室

入口：Unity 菜单 **Starframe → 开发工具 → 体块地图工作室**。这是独立开发工具，现有游戏首页和出击流程没有接入地图编辑。

## 制作可复用资产

1. 选择“体块资产”，点“新建”保存一份 `.asset`，或从左侧打开示例。
2. 右侧“批量造型”可以生成方盒、小行星、圆环，也可叠加、挖空或生成空心外壳。相同随机种子生成相同结果。
3. 使用放置、删除、涂材质笔刷修改细节；支持笔刷尺寸和多个材质槽。所有体块都是完整基础立方体，没有飞船组件。
4. 设置格子尺寸、每格血量、停火重置时间和质量密度后保存。修改源资产会影响地图中引用它的实例。
5. “破坏预览”只修改临时副本；“重置预览”恢复完整造型。“导出资产 Prefab”可供普通 Unity 场景引用，运行时自动生成网格和物理。

视窗：中键旋转，Shift+中键平移，滚轮缩放，F 聚焦，X 切换放置/删除，Ctrl+Z 撤销。右侧面板可以滚动。

2026-10-24 更新：地图资产默认复用船体的四种基础模型和塑料材质。右侧“笔刷”选择正方体、斜面体、半高方块或四棱锥；R 绕光标附着的标准格子面旋转。右侧“船体外观 → 基础色”修改整份资产的颜色，白色保留原船体材质；“当前颜色槽”和涂材质笔刷控制局部配色。新旧资产均保留完整单元格碰撞，半高、斜面和四棱锥的视觉体积不改变占格。

## 摆放地图

1. 切换“地图布局”，新建地图或打开 `MapWorkshopDemo.asset`。
2. 左侧选择源资产，在“摆放资产”模式下单击视窗，将资产放到当前水平编辑平面；平面高度和吸附间距在右侧设置。
3. “选择/移动”模式下单击选择、拖动平移。右侧可精确输入位置 XYZ、旋转、统一缩放、血量倍率和初始漂移/旋转速度。
4. R 旋转 90°，Ctrl+D 复制，Delete 删除。F 聚焦选中对象；清空选择后 F 聚焦全图。
5. “下半区批量散布”可按种子生成小行星带，自动将整份资产放在 Y<0 的地图范围内；上半区保留飞行空间。
6. 保存地图。玩家和敌方出生点目前仅作为数据，供之后的关卡与波次脚本使用。

## 物理试玩

在地图工作区点“打开物理试玩场景”，然后按 Unity **Play**。也可直接打开 `Assets/_Starframe/Maps/Scenes/StudioPhysicsPreview.unity`。

| 操作 | 功能 |
| --- | --- |
| 右键拖动 | 自由观察 |
| WASD、Space/Ctrl | 前后左右、上下移动 |
| 滚轮、Shift | 调速、加速 |
| 左键 | 对准中心格子造成 40 伤害 |
| Shift+左键 | 强力破坏探针 |
| 中键 | 推动瞄准的资产，观察漂移和碰撞 |
| Unity Stop | 停止试玩，源资产和地图保持原样 |

编辑器中的破坏预览不运行刚体。试玩场景才启用物理：**完整资产一个无重力动态刚体；打断后，每个面相连的碎块成为独立刚体**。继承线速度、角速度，并加入很小的分离速度。存活体块不会因为断连而消失，碎块仍有碰撞并能继续摧毁。

## 数据与性能

没有地形区块，也没有每格 GameObject / Rigidbody。每个完整资产或断裂岛是一份合并网格、一个刚体和合并的复合 BoxCollider；空格保留真实形状。完整重复实例共享网格。仅在视觉模型确实完全遮挡时剔除隐藏面；船体倒角模型略小于单元格，真实接缝内的面保留，以免露出空腔。只有体块被摧毁时才重建该资产的网格、碰撞和连通关系，同一批伤害合并处理。

满血格子不保存当前 HP。仅最近受击的格子记录临时剩余血量；默认停火 **2 秒**后直接丢弃记录，视为满血，不逐帧回血。被摧毁的格子不会因此长回来。默认每格血量 **100**、密度 **100 kg/m³**、碎块分离速度 **0.5 m/s**，均可在工具右侧调整。每份源资产上限 131072 格；这不是超大规模地图性能保证，复杂散碎资产会产生更多碰撞体。

现有激光已经接入地图体块的精确命中、伤害和穿透，飞船的碰撞扫掠也会推动动态地图资产。普通“导出地图场景”包含 `SpaceMapRuntime`、光源和相机；试玩导出另带开发相机。没有修改游戏首页、关卡结算或敌人波次。

| 位置 | 内容 |
| --- | --- |
| `Assets/_Starframe/Maps/Assets` | 体块源资产 |
| `Assets/_Starframe/Maps/Layouts` | 地图实例布局与出生点 |
| `Assets/_Starframe/Maps/Materials` | 可编辑的 URP 材质 |
| `Assets/_Starframe/Maps/Prefabs` | 工具导出的 Prefab |

## 核实参考

参考了 [Mojang 的子区块协议说明](https://mojang.github.io/bedrock-protocol-docs/guides/sub-chunk-request-system-v1-18-10/) 和 [Microsoft 的模拟/渲染距离说明](https://learn.microsoft.com/en-us/minecraft/creator/documents/simulationrenderdistanceguide?view=minecraft-bedrock-stable)，但按本项目要求使用移动资产和断裂岛，而非固定地形区块。稀疏临时血量是本项目的定制规则，不声称 Minecraft 使用同样的耐久算法。动态碰撞采用 Unity 的复合基础碰撞体，依据 [Unity Mesh Collider 限制](https://docs.unity3d.com/6000.3/Documentation/Manual/mesh-colliders-introduction.html) 避免以非凸 MeshCollider 驱动自由漂浮物体。
