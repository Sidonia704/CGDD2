# Flare motion stability

The old presentation updated only in FixedUpdate while the chase camera followed an interpolated ship. At 350 m/s and a 20 ms physics step, inherited motion jumped 7 metres per update. The shader and meshes contain no trail or directional stretching; the timing mismatch is the identified movement artefact.

FlareWorld now samples previous/current visual age each LateUpdate. Inherited translation, ejection, scale and colour use this same age without advancing logical decoys. Burst flashes have a continuous 45 ms attack instead of an instantaneous scale jump. Gameplay values, original random sampling, yellow colour and pool lifetime remain unchanged.

Validation: 17/17 focused EditMode tests. New tests cover 30/60/144 Hz rendering against 50 Hz physics at inherited velocity (350,70,-90), camera-relative displacement, uniform scale, unchanged lure position and continuous burst onset. Existing lifetime, pooling, launch-cone, cooldown and threat forecast tests pass.

Native offscreen images `moving-0.png` through `moving-5.png` use the production shader, native range post-processing profile and moving camera at 0.8/0.8167/0.8333 and 1.2/1.2167/1.2333 seconds. Generated by `tools/FlareMotionVisualReview.cs` in an isolated preview scene; no user ship or saved scene was modified. These are deterministic render samples, not a real-time Play-mode capture or a performance measurement.
