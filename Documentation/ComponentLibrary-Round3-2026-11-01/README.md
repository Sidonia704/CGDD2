# Component library round 3 — audit, cleanup and size pass

Editor-only work on the 37-part ship library. Nothing here changes weapons balance, flight, AI, mission flow or map content, and no map assembly was started.

## Scope

1. Audit the component assets again for duplicates and leftover test/experiment content.
2. Finish the parts that were still incomplete.
3. Delete what is genuinely unnecessary.
4. Optimize part dimensions against what the assembly system actually needs.

Machine-readable audit: [audit-before-cleanup.txt](<Documentation/ComponentLibrary-Round3-2026-11-01/audit-before-cleanup.txt>) / [.json](<Documentation/ComponentLibrary-Round3-2026-11-01/audit-before-cleanup.json>) · after cleanup: [audit.txt](<Documentation/ComponentLibrary-Round3-2026-11-01/audit.txt>) / [.json](<Documentation/ComponentLibrary-Round3-2026-11-01/audit.json>) · delete log: [cleanup-log.txt](<Documentation/ComponentLibrary-Round3-2026-11-01/cleanup-log.txt>).

## How it was measured

- Unity 6000.3.25f1, real `AssetDatabase` work in the open Editor: 37 modules read from `ModuleDatabase`, 37 `ModuleDefinition` assets, 14 `WeaponDefinition` assets, and a full reverse-dependency map (`GetDependencies` over every asset, 958 before / 316 component files after).
- Three independent read-only static audits ran in parallel: code/UI wiring completeness, duplicate/orphan assets with a GUID reference graph, and mesh-AABB versus reserved-cell dimensions (55 mesh assets parsed from `m_LocalAABB`).
- The Unity reverse map is the authority for "used"; the static GUID audit is the cross-check. They agree on every component asset.

## What the audit found

### Wiring is complete for all 37 parts

Every shape has a definition in the database, a baked mesh, a material, a normal icon and a selected icon, a `module.<Shape>` and `module.short.<Shape>` localization entry, a category and a weapon definition where applicable. 27 expansion shapes use `Icons/Expansion/*`, the original ten keep their original icons. There are no duplicate shapes and no duplicate definitions.

### The real duplicates were import copies, not content

| Item | Count | Evidence |
|---|---:|---|
| `Art/Models/Modules/Expansion/*.fbx` | 27 | Byte-identical to `assetsForCodex/*.fbx`, zero GUID references, regenerated by the installer |
| `assetsForCodex/thruster6 1.png`, `thruster6s 1.png` | 2 | Byte-identical to `thruster6.png` / `thruster6s.png`; inside the user source folder |
| `Art/Models/Modules/*.fbx` (original nine) | 9 | Zero references, but the only surviving source copies of the original models — kept |
| `Art/Weapons/LaserCannon*` (mesh, edges, material, source) | 4 | Zero references, but the only original laser art — kept |

No module definition, baked mesh, icon or material was orphaned: all of them are reachable from `ModuleDatabase` → `FlightTuning` → `Hangar` / `ShipEditor` / `FlightRange`.

### Two parts did not match their reserved space

- **Railgun2** reserved `2×1×5` (10 cells) but its model is only 0.822 cells wide — 38% box fill, one wasted column, and the mesh sat off-centre inside that column.
- **Power2** fell to `1.852³` inside a `2×2×2` box because the installer's absolute `0.495` scale cap binds on it, while Block8 and Shield2 reach `1.980`. Every other axis in the library is forced by the model silhouette, so these two were the only real over-reservations.

No mesh overflows its reserved cells, and every expansion part's floor sits exactly at `y = -0.5`.

### Two completion defects

- **Multi-barrel weapon glow**: `ModuleGlowAccents` placed one accent at the *averaged* muzzle, so Gun1/2/3 and Missile2 drew their bore glow between the barrels instead of on them.
- **Placement vs firing mismatch**: `WeaponClearance` validated only the averaged muzzle while `ShipWeapons` rejects a slot if *any* barrel is blocked. A four- or six-barrel gun could be placed as valid and then read as blocked in flight.

## What changed

| Change | Detail |
|---|---|
| Deleted duplicate import copies | 27 unreferenced `Art/Models/Modules/Expansion/*.fbx` (+ `.meta`), each re-checked for zero references immediately before deletion |
| Railgun2 repack | `2×1×5` → `1×1×5`; the existing baked mesh is translated by −0.5 on X (identical geometry), its muzzle follows, occupancy and the code fallback updated |
| Power2 refill | Mesh scaled 1.069× about its own centre to `1.980` per axis, floor unchanged at −0.5 |
| Per-bore glow | One accent per declared bore for weapons; single-nozzle and Thruster6 nozzle paths unchanged |
| Per-bore placement clearance | Placement now checks every bore exactly like the firing check |

Blueprint compatibility: Railgun2 now occupies *fewer* cells, so an older blueprint still loads and cannot gain overlaps; its model and muzzle moved with the new single column. No other part's cells changed.

## Deliberately not changed

- **Original nine source FBX** (only copies) and `assetsForCodex/**` (user-supplied source; still the input of the installer and of the recorded source hashes).
- **Original ten definitions and meshes**: the nine originals sit at `y = -0.49` and Core at `-0.42` (it floats 0.08 above the cell floor) while expansion parts sit at `-0.50`. Normalising them would touch the frozen original assets, map hull seams and the preview path, so this is reported instead of changed.
- **Balance values**: no mass, HP, thrust, power, damage, cadence or recovery number was edited.

## Remaining gaps (proposals, not done)

1. `cost` is 0 on all 37 parts, so the hangar cost readout is always 0 and mission budgets rely on provisional pricing. Filling it needs a pricing decision.
2. Armor1–4 are filed under the *Shields* category, so the library header says Shields while the panel says Armor.
3. The 1-cell Shield still reuses the Cube mesh; Shield2 has its own model.
4. The HUD ship silhouette falls back to a bounding box for the 27 expansion shapes.
5. Hover/face snapping uses box geometry for expansion shapes, so clicking a real sloped or inset surface can be rejected instead of snapping.
6. Missing content that the current code could support with data plus art: mid-tier power (2–4 cells), mid-tier shield, a 1–2 cell point weapon, a charge/toggle weapon, sloped armor, and a multi-nozzle thruster other than Thruster6.
7. Pre-existing, unrelated to this pass: the old `Starframe/Refresh supplied models only` menu (`VisualPowerUpgrade`) still points at nine `assetsForCodex` source names (`block1…block4`, `core`, `lazer`, `psu`, `thruster1/2`) that no longer exist, so it throws if invoked. It is not used by the shipped pipeline.
