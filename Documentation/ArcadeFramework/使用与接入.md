# Starframe 游戏框架

入口场景：`Assets/_Starframe/Scenes/Frontend/Hangar.unity`。在 Unity 按 Play；构建场景顺序已以 Hangar 为首。

## 已接通的玩家流程

- 首页上部显示当前舰船的真实 3D 模型。中键旋转、滚轮缩放；可换船、进入装配、分配武器组。
- 下部两张行动卡进入出击确认。重新选择难度，检查预算、唯一核心、合法占格、部件定义和面连接；可换船或返回装配修改后继续确认。
- 确认后建立独立战斗快照。两个关卡的实际内容尚未设计，当前显示已确认页面；不会假装已经完成关卡。
- 靶场可分别指定每份蓝图的数量，并选择静止、仅飞行、原地射击或完整对战。在场内按 Esc 也能改训练模式、重置靶机或打开设置；菜单期间战斗继续。
- 设置包含显示模式/分辨率/刷新率、VSync/帧率、画质/FOV/Bloom、四类音量、飞行灵敏度/平滑/反转/按键、减少闪光、中英文。修改先暂存；独立版本改变显示模式有 15 秒确认恢复。

## 数据和扩展入口

| 内容 | 修改位置 |
|---|---|
| 部件质量、血量、推力、占格、电力、护盾、资源成本 | `Assets/_Starframe/Settings/` 下的 ModuleDatabase / ModuleDefinition 资产；从 FlightTuning 的 Database 引用进入 |
| 激光伤害、速度、射速、耗能、触发方式 | 对应 ModuleDefinition 的 WeaponDefinition 引用 |
| 飞行基础参数、转向响应、加力、视角、尾焰 | `Assets/_Starframe/Settings/Flight/FlightTuning.asset` |
| 战斗恢复、重生、特效、默认靶机 | `Assets/_Starframe/Settings/Flight/BattleTuning.asset` |
| 两个关卡与预算/难度系数 | `Assets/_Starframe/Settings/Game/Missions.asset`、`ice.asset`、`frontier.asset` |
| UI 配色、磨砂、准星和各部分布局开关 | `Assets/_Starframe/Resources/UI/WorkbenchTheme.asset` |
| 中英文文案 | `Assets/_Starframe/Localization/GameUI.csv`；修改后执行 `Starframe > Localization > Install Chinese and English` |
| 首页和关卡缩略图 | MissionDefinition 的 Thumbnail，可直接替换占位截图 |

当前未定价部件只在关卡预算校验中暂按每件 10 资源估算，确认页明确提示。模块原有成本未被批量改写；将正式成本填入模块后会优先使用正式值。靶场没有关卡预算门槛。

### 接入真正关卡

给 MissionDefinition 的 `Scene Name` 填入已加入 Build Settings 的场景名。出击按钮会重新校验，然后加载该场景。

关卡从 `MissionSession.Current` 读取关卡 ID、难度、船体快照及确认预算。每次读取都会返回深拷贝；战斗破坏不会回写工作区和蓝图。也可以订阅 `MissionSession.LaunchRequested` 接入后续流程。

关卡结束时调用 `MissionResults.FinishAndReturn(outcome, summary)`，即可显示统一的行动报告，包含行动时间、击毁数、伤害和幸存部件；「重新整备出击」仍经过舰船与资源确认。胜负由关卡脚本决定，接口不会自行判胜或发放资源。报告和蓝图也互相隔离，同一航次仅结算一次。

实际地图、波次和胜负条件仍由后续关卡设计提供。本轮没有添加新武器或重做平衡。

### 武器编组

每件武器按稳定部件 ID 单独归组。可以在下方船体上点选，或从右侧名单点选，再点击上方组卡；连线和着色表示所属组。每组可改名、绑定键盘或鼠标，最多显示 8 组；新建组默认绑定鼠标左键。保存蓝图会保留编组；旧蓝图自动进入默认左键组。

进入战斗时所有武器组均启用。按数字键 1–8 可切换对应组的启用状态，再按该组绑定的开火输入射击；默认左键组也遵循启用状态。飞行 HUD 左侧按 1–4、5–8 两行显示各组启用状态与当前存活武器数量。尚无武器的组仍会显示，数量为 0。关闭的组不射击、不耗电、不参与预瞄；启用状态只保留在本次战斗中，不改写蓝图。

`WeaponDefinition` 已提供 Hold / Press / ChargeRelease / Toggle 及需要锁定的触发通道，`ShipWeapons` 共用冷却、电力分配和取消逻辑。当前攻击执行器仍是弹丸；未来导弹的追踪目标和持续光束的执行器需要随新武器内容加入，不能只改触发类型就变成导弹或光束。

### 存档隔离

原有具名蓝图仍在 `Application.persistentDataPath/Blueprints`，没有转换或覆盖用户文件。工作中的舰船单独保存在 `Workspace/current-ship.json`，保留备份；配置在 `Settings/preferences.json`。战斗、预览和确认快照各自独立。编组写入失败会保留未保存的草稿并允许重试。

## 单独撤回视觉改动

`WorkbenchTheme` 内可分别关闭玻璃配色、装配布局、飞行布局、准星/目标指示器、雷达、船体状态图；重新进入页面生效。这些开关不会修改舰船、武器参数或蓝图。旧 UI 源码备份仍保留在 `Documentation/UIRefresh-2026-10-18/Before` 和 `Documentation/UIHitFeedback/Before`。

首页框架集中在 `Scripts/Runtime/Construction/App`；不想以首页启动时，可在 Build Settings 将 ShipEditor 调至首位，保留其余框架供之后接入。

## 验证

普通 EditMode/PlayMode 套件验证存档、设置、部署、分组、实际移动射击、残骸和跨页面返回。手动压力用例为 `FrameworkScaleProbe.MeasureP1P2P3WithRealFlightCombatAndAllAccumulatedWreckage`，标记 Explicit，不在普通测试中运行；结果写入 `Temp/ArcadeFrameworkScaleReport.json`。编辑器测量包含测试框架开销，不能直接作为独立运行帧率承诺。

构建前会保留运行时创建材质所需的自定义着色器，避免 Shader.Find 在独立版本因剔除而失效。新增语言资源后应重建 Addressables；构建结果和本轮验证记录见同目录的验证说明。
