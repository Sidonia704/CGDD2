4. 波次、胜负与关卡时长
每波前有固定读条／倒计时。上一波没清完，计时到了仍生成下一波。中间清空场上敌人后，玩家可以按键提前生
成下一波，生成后重新开始一轮完整倒计时。
本轮补充：关卡初始化后开始首个倒计时；具体时长作为关卡配置，本文不填写秒数。
允许跳波 = 存活敌人数为 0 AND 待生成队列为空 AND 还有后续波次
胜利 = 所有波次均已生成完成 AND 待生成队列为空 AND 存活敌人数为 0
失败 = 玩家核心被毁
 最后一波生成完后，不再开始下一波倒计时。
 中间清场不能判胜；生成中的敌人也计入未完成状态。
 最后一波存活敌人清完才通关，不因到达约 15 分钟而结束。
 用户“四波、13 分钟全部刷完”是例子，不固定所有关卡都为四波。
 波间没有额外全修、资源、改船或随机奖励；恢复始终遵守同一规则。
 本轮补充：同一结算步死亡与清场同时发生时失败优先；结束事件只触发一次。

5. 建造、蓝图和预算
5.1 结构与编辑
用户确认三维格子自由连接，可用多格大型部件。每船恰好一个核心，存在发电机等组件。
本轮采用以下基础编辑规则：
 面接触算连接，棱或角接触不算；格子旋转使用直角旋转。
 不允许占格重叠。多格部件只是一件组件，具有统一 ID、血量与功能。
 保存可保留超预算或尚未完成的设计，出击必须通过合法性校验。
 基本交互为放置、删除、旋转、单轴镜像；不做复杂组合编辑和任意角度摆放。
 首发武器作为整件零件装船，不在首发编辑器中拼装炮管或连接增益模块。
5.2 预算
蓝图总 cost = 所有安装零件 cost 之和（本轮采用简单加和）
出击成本条件 = 蓝图总 cost <= 所选关卡与难度的额度
可以不花完预算，剩余额度没有奖励。自由拆装只改变蓝图总成本，没有库存、交易或拆除损失。
出击还检查：恰好一个核心、所有出战部件与核心连通、占格合法、零件配置完整。喷口被挡只影响功能，显示提
示；本轮按不因此禁止保存或出击处理，不引入预算之外的数量限制。

6. 运动、鼠标朝向与射击
6.1 飞行控制
允许前后、左右、上下平移及俯仰、偏航、翻滚。鼠标控制船头偏转，稳定时船头朝向鼠标目标；并非松手后无限
自转。没有自动回到世界水平的规则，翻滚保留独立操作。
自动减速降低平移速度。鼠标跟随转向与自动平移制动使用当前推进／机动能力并消耗能量；供能不足使响应变慢
，不能直接把速度或角度瞬间归零。
本轮补充：制动只能使用当前可用的反向能力；相应推进失效或无供能时，不能凭空完全刹停。建造和靶场应反馈
缺失方向。最高速度、转向上限、灵敏度及具体按键后续调试。

AND 如果跟踪锁定目标，则目标处于有效视界
未锁定的前向射击不要求前面一定有敌人。炮塔没转到位、丢失射界或锁定目标出视界时停火；自己的船体挡住时
也停火，没有自伤。射击后仍要做实际命中检测，锁定不等于必中。
本轮补充：目标出视界时可保留选中身份，但标记不能跟踪射击；玩家解除锁定后回到非导弹武器前向模式。炮塔
转速、误差阈值、射程、弹速与提前量后续配置。
6.3 碰撞与越界
船体和场景、其他船有物理阻挡，但没有撞击伤害。碰撞滑动或弹开强度以后调手感。
越界超过一定时间后强制传送回界内。具体时间未定。本轮补充：使用有效回场点并检查空位，避免嵌入障碍；不
附赠回血或充电；敌船也使用边界回传，避免永久飞走导致不能清场。

7. 血量、断连与恢复
7.1 损坏与死亡
每部件独立血量，核心也是独立血量。被毁块直接消失；不再与唯一核心连通的整片船体也消失，功能随之失效。
质量在消失时减少，恢复时加回；普通掉血不减重。
只有核心毁坏导致死亡。失去全部武器、推进或发电能力不自动判死。敌我共享这些规则。
7.2 整船脱战
按整船是否继续受到船体伤害计时，等待时间暂定 1 秒。自己开火、对敌造成伤害不重置。
按“船体受伤”的表述，本轮明确：护盾完全吸收且部件未掉血的命中不重置；发生有效船体伤害则更新最近受伤
时间，并让所有尚未出现部件重新读条。
7.3 存在部件回血
仍存在但未满血的部件在脱战后回血。再次受伤时暂停回血，保留已恢复血量，再扣掉本次伤害。
本轮先用每件已有恢复时间作为从零到满的基准：回血速率 = 最大血量／恢复时间。若以后需要分别设置维修和
重建速度，再扩展配置。未毁部件保持正常功能，不额外做按血量连续降效。
7.4 缺失部件重建
1. 整船已脱战。
2. 缺失部件在原蓝图位置有至少一个当前存在的相邻支持部件。
3. 累计该部件自己的恢复时间。
4. 完成时整件满血出现，恢复模型、碰撞和功能。
5. 新出现部件为后续缺失位置提供支持。
邻居只需存在，不必满血。多邻居不提高同一部件速度；密集结构的优势是更多位置可以同时恢复。
再次发生船体伤害：未出现部件读条归零；已经出现的部件保留当前血量。本版没有修复技能、次数限制或修复资
源消耗。
本轮补充：断连消失部分也进入缺失状态，必须从仍连着核心的船体逐步长回；不由消失片区自发再生。所有支持
都消失时停止并清空该位置进度。核心死亡后本次模拟结束，不再重建。

8. 储能、供能和护盾
8.1 能源顺序
先由发电满足需求，不足时使用储能，储能也不足时所有正在工作的系统按同一比例降低输出。武器降射速，护盾
参与分配，敌我一致。
本轮统一术语：E 为当前电量，C 为容量，G 为有效发电速率，D 为当前总请求功率。速率和容量不能混用。
初版采用全船共享能源，不添加布线、电网分区、供能优先级和电池放电功率上限：
要求 dt > 0；G、D 非负；0 <= E <= C
D = 0 时，r = 1
D > 0 时，r = min(1, (G + E / dt) / D)
各系统获得的功率 = 自己的请求功率 × r
E_next = clamp(E + (G - D × r) × dt, 0, C)
同时收集需求再分配，避免消费者遍历顺序造成抢电。满额请求与实际输出分开，不能对已经降额的数值重复乘 r。
8.2 输出与损坏
 武器：按供能比例推进射击周期／充能进度，降低射速，不同时降低单发伤害。
 推进：降低加速度、平移制动与主动转向能力，不瞬间截断现有速度。
 护盾：作为消费者参与，具体工作需求和降额表现留在护盾模块中细化。
 电池消失：容量减少，当前电量截断到新上限。电池恢复只增加容量，不自动补电。这是本轮补充的防止重复
免费充电规则。
基础炮建议按实际供能积累发射进度，达到一发门槛后生成一发完整攻击。使用该模型时，不能扣一次平均功率后
又把同一发能量扣第二次。停止射击或被挡时不继续预充；进度是否保留属于武器后续细节。
8.3 范围护盾的边界
已确认护盾有空间作用范围，敌我同规则，供能不足会影响护盾工作。球形或其他形状、重叠伤害、护盾容量、击
破余量、恢复和维持耗能需要在后续护盾模块明确。
首发排期按简单几何范围和基础表现估算；本文不自行指定多层减伤公式。没有删掉护盾系统，也没有将未定义的
细节当成已完成实现。

9. 机动汇总与喷口算法
9.1 已通过的方案
用户同意：推进器按六方向汇总，转向由部件机动贡献和质量决定；安装位置不产生真实力矩。布局仍影响保护、
连接、质量和遮挡；装偏不会因此自发持续自转。
用户同意：喷口采用有限方向档位近似偏转；部分遮挡移除对应方向，全部遮挡则失效。结构变化后重新检测。
9.2 计算关系
每个推进器记录额定推力、耗能、局部推进方向和允许偏转档位。尾焰方向与推进方向相反：遮挡检测尾焰空间，
运动计算推进方向。
M = 所有当前存在部件的质量之和
推进器在方向 d 的贡献 = 额定推力 × max(0, 推力单位方向与 d 的点积)
Td = 对所有有效推进器求该方向贡献之和
满供能加速度 ad = Td / M
实际输出 = 满供能能力 × 本步供能比例
对可偏转喷口，在未被挡住的档位中取当前所需方向上贡献最大的档位。这是已接受的街机能力模型，不是完整物
理推力分配。Unity 的点积 API 可用于方向投影。Unity 6：Vector3.Dot
六方向数值是不同输入下的上限，不能把同一推进器同时算出多倍推力。本轮建议把组合方向输入换成和不超过 1
的方向权重后混合能力；它是有意保守的简化。平移和转向也共享同一推进资源预算，不能一份额定功率同时支撑
两个满额输出。
转向能力由现有部件配置的机动贡献求和，再按质量尺度换算。鼠标飞控读取这一能力，逐步追上目标朝向；不瞬
间对齐，也不增加逐喷口真实偏心力矩。
9.3 更新与遮挡
初始化、部件出现或消失后：合并本步变化 → 更新连通 → 检查受影响船体的喷口 → 重算质量和能力。普通未致
命掉血不需要改变质量或结构。
每个候选喷口方向检查短距离净空区域，宽度要覆盖喷口，不能用零宽单射线冒充完整净空。第一版可重查该船全
部喷口；测出过慢后再维护局部依赖索引。无需每帧把全船部件与所有喷口两两比较。
净空针对自身船体与配置的局部范围；不由远处环境障碍永久改变喷口配置。建造提示可用档位，让玩家知道部分
遮挡如何影响推进。具体方向档位、角度和净空距离以后配置。
9.4 稳定性要求
质量只在部件消失时减少，恢复时增加。残船质量降低后同推力下加速度可能变高；速度和转向上限以后调试。
性能从当前有效部件重新求和，不在旧值上反复增减或重复乘供能比例。零质量、零推力、零供能等情况使用明确
分支，避免除零、NaN 或失效部件仍贡献性能。

2. 检查核心死亡；终局后停止进一步战斗。
3. 合并结构变化，检查断连，更新净空与基础性能。
4. 按一致快照评估恢复资格、累计进度，集中提交部件出现。
5. 提交恢复引起的结构和性能变化。
6. 收集有效操作需求，统一供能，再执行运动和开火。
7. 后续命中进入受控事件处理；检查波次和清场，刷新统计与表现。

 1000 部件蓝图能保存、加载、正确统计成本并出击；多格占用不重复计算。
 同一步重复命中或多块毁坏不会重复扣除贡献。
 切断连接桥后整片消失，质量、武器和供能同步变化。
 未毁块回血保留，缺失块满血重现，再受船体伤害后未出现块全部重计时。
 核心死亡立即结束，不会在失败后重建并恢复战斗。
 电池消失容量收缩，重建不免费补电；缺电同比分配、武器降射速。
 未锁定时直射与炮塔前向射击；锁定炮塔先转到位；遮挡、射界和视界正确停火。
 喷口因缺口出现而恢复方向、因船体重建而再次被挡。
 中间清场不胜利，最后一波生成中不误判；跳波重置完整计时。
 碰撞有阻挡无伤害；越界返回不嵌入障碍，敌人不永久离场。
 两关均可从主菜单进入、失败重开、成功结算，蓝图不会被战损覆盖。

16. 本轮补齐的小幅规则

6. 断连部分同样按缺失部件逐步重建；失去所有支撑时取消该位置进度。
7. 电池恢复仅增加容量，当前电量不凭空增加。
8. 同刻死亡与清场失败优先；待生成敌人不允许提前胜利。
9. 越界回传检查空位、不补血补电，敌我同用。

19. Unity 与 AI 的具体协作方式
本节是适合当前熟练度的流程建议，不要求学习新的大型框架。
1. 一次给一个可验证任务。 例如“输入部件表，输出仍连接核心的 ID 列表”；不要一次要求生成完整造船、战
斗、存档和 UI。
2. 先写输入和结果。 提供数据结构、调用时机、允许改哪些文件、一个小例子，以及怎样在 Unity 中验证。
3. AI 提供脚本和接入说明。 明确挂在哪个对象、Inspector 有哪些字段、依赖哪些对象；不要把缺失场景引用留
到运行时报错才猜。
4. 用户控制场景和 Prefab 接线。 初期避免让 AI 同时大改场景文件、资源层级和多份脚本；先熟悉少量对象如何
协作。
5. 每次先编译，再跑小场景。 有错误就提供完整报错与堆栈，修好当前任务后再叠功能；不累计几十处编译错误。
6. 保留可运行版本。 一个功能通过就做版本记录，避免下一次生成覆盖能工作的基础。
7. UI 最后美化。 先用简单布局把按钮、成本、能量、船体状态接通，确认逻辑后再做视觉调整。
优先交给 AI 的任务：纯数据结构、蓝图序列化、成本求和、连接图遍历、参数面板脚本、小范围 UI 逻辑。必须在
 Unity 中人工核对的任务：引用接线、物理与炮塔层级、碰撞层、镜头手感、渲染效果和性能。
每个任务的完成标准是“项目编译、场景能运行、行为符合文档”，不是“代码已经生成”。不承诺零 bug；用第
 14 节的关键例子检查组合行为。
