# 地图与船体共用基础体块外观

- 默认使用 `Assets/_Starframe/Settings/Modules/ModuleDatabase.asset` 中的 Cube / Wedge / Slab / Pyramid 模型及其原始塑料材质。船体模型更新后，地图也从同一资源读取，不维护近似替代模型。
- 四种体块：**正方体、斜面体、半高方块、四棱锥**。地图工作室右侧“笔刷”有四个选择按钮，R 或旋转按钮绕光标附着的标准格子面旋转。批量造型也使用当前体块种类。
- 颜色入口：右侧 **船体外观 → 基础色**；白色保留船体原色，选择其他颜色进行乘色。下方可添加/调整颜色槽，用涂材质笔刷给局部体块换槽。颜色保存在源资产，地图中引用该源资产的实例同步使用；飞船材质文件不被改写。
- 保存数据新增 `VoxelCell.shape` 与 `quarterTurns`。原有数据缺省为正方体、零旋转。形状、朝向和颜色槽在保存载入及断裂碎块中保留。
- 碰撞、占格、伤害和连通仍按完整 1 格处理，和船体规则一致。渲染采用整资产合并模型，不创建逐格 GameObject 或 Rigidbody。

## 接缝修正

实际检查四种源模型，所有非退化三角形的绕序与法线方向一致，没有反向法线。Cube 的视觉边长约为 0.98 格；不能用其 1 格碰撞占用推断模型之间没有缝隙。旧的隐藏面剔除条件会删掉缝内可见面，形成类似反法线的漏面。

现在仅当模型的视觉体积确实覆盖完整单元格、接触面位于真实格子边界时才剔除；当前有缝的船体模型保留封闭面。法线、切线和原始三角形方向不变。`SeamsFixed.png` 为修正后的实际预览。

## 验证与兼容

`EditorSmoke.json` 记录实际点击四种按钮、旋转、放置、保存载入和修改基础色的结果；同时逐字节比较原船体材质，确认未改变。`FourShapes.png`、`FourShapesTinted.png` 展示同一模型的原色和改色。完整测试见本目录 `EditModeTests.json` 与 `PlayModeTests.json`。

现有 5 份资产只绑定共用外观库，保留原体块坐标、材质槽编号和地图布局。更改前源资产的字节备份保存在 `Before/`，文件名对应其原 GUID；原材质文件与模型没有修改。
