# 星构 Starframe - 当前测试靶场范围

依据 Game_Design_v1.0_ZH.pdf（v1.0，2026-09-25）全文整理。
当前实施范围以本次用户请求为准：建立工程目录和可运行的太空测试场景，以中央红色金属立方体验证 Unity MCP 的场景、资源、材质、照明、保存及运行能力。
PDF 中完整游戏的排期和历史协作建议是参考资料，不是本次全部执行的指令。

## 当前交付
- 场景：Assets/_Starframe/Scenes/Testing/SpaceTestRange.unity。
- 深色星云与星点天空，冷暖光照、环境反射、URP Bloom 和色调映射。
- 世界原点红色金属立方体，独立材质与可复用 Prefab，BoxCollider。
- 环境、测试对象、照明、相机、GameplayRoot 分组，为后续逻辑接入留入口。
- 按 Play 可运行场景；本轮没有宣称完成飞控、武器、伤害、供能或造船功能。

## 靶场应验证的需求
1. 试飞、试射、受损与机动；与正式战斗共用船体、武器、恢复、供能逻辑，避免两套模拟。靶场不检查关卡预算，仍要求可运行结构；退出丢弃临时血量和电量。
2. 三维格子船体：唯一核心、稳定部件 ID、面邻接、多格组件去重、无重叠；蓝图与运行战损分离。敌我共用底层规则，AI 仅生成操作意图。
3. 部件独立血量，仅自身血量归零时摧毁。断连片区和核心毁坏后的所有存活部件均保留为带碰撞、可摧毁的漂浮残骸（不提供舰船功能），不按时间、数量或越界清理。核心存活时原船按缺失格逐步重建；核心毁坏先转移全部存活部件，再触发死亡和重生，新船与旧残骸独立。
4. 整船有效船体伤害重置脱战计时，暂定 1 秒；射击和护盾完全吸收不重置。存在部件脱战回血，缺失部件依赖当前相邻支撑逐步满血重建。再次受伤清空所有尚未出现部件进度，新出现部件下一次评估才提供支撑。
5. 全船共享供能：先发电，再储能，不足则所有消费者同比降低输出。武器降射速、推进降响应，单发伤害不随供能比例降低。电池消失缩容，恢复不免费补电。
6. 六方向推力汇总、俯仰/偏航/翻滚和鼠标船头朝向；按当前能力、质量、供能逐步响应，不瞬间归零。喷口采用离散方向，结构变化时重查净空。
7. 基础直射炮和跟踪炮塔共用发射内核；前向非导弹射击不要求锁定。炮塔需对准、有射界、无遮挡，锁定目标需在有效视界。
8. 物理碰撞有阻挡、无撞击伤害；越界返回有效空位，不补血补电。
9. HUD 后续展示部件/武器/能源状态，不使用整船总血条。
10. 之后需要按单船 1000 部件、典型敌人配置和全部波次积压测量，未测出性能前不假定 FPS，也不暗加部件或同屏敌人上限。

## 数据与更新顺序
- 配置：只读部件/武器等定义，放在 Data。
- 蓝图：ID、类型、位置、朝向，与本次运行状态分离。
- 固定步：收集命中 -> 立即失效/核心终局 -> 合并结构变更/连通/净空/性能 -> 快照评估与提交恢复 -> 统一需求/供能 -> 运动与武器。
- 表现只消费结果；避免每个部件独立 Update 和碰撞回调递归互删。

## 后续开发建议顺序
1. 少量部件的船体/蓝图数据与连通校验。
2. 船尾相机、六向运动、基础射击和目标命中。
3. 部件损伤、断连、脱战回血和逐步重建。
4. 共享供能、推进遮挡、武器/护盾输出。
5. 重复实验和规模测量，再考虑正式关卡。

## 尚待确定
配件 cost/质量/血量/恢复时长，武器射速/伤害/弹速，飞控参数、护盾几何与重叠规则等仍属后续配置；不把视觉立方体当作正式船体或平衡定值。
